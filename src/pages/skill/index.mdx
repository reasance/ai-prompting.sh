# Install as a Skill

A **Skill** is a self-contained instruction bundle that an agent host loads on demand. The
[Agent Skills standard](https://agentskills.io) defines a `SKILL.md` file with YAML frontmatter and
a markdown body, plus any files it references. `ai-prompting` ships one directory: `SKILL.md`,
`references/`, `agents/`.

When loaded, the host agent reads `SKILL.md`, optionally pulls in `references/*.md` if a deeper
context is needed, and uses the agent's own language model to do the semantic rewrite. The CLI
provides a deterministic baseline; the Skill provides creativity.

## Install

The package ships a Node-only installer that copies the Skill directory to where each host looks
for skills. It is a script, not a CLI subcommand — run it by path:

<CodeBlock code={`# global install
node "$(npm root -g)/ai-prompting/scripts/install-skill.js"

# project install
node node_modules/ai-prompting/scripts/install-skill.js`} />

For every host it detects, it writes:

- `~/.claude/skills/ai-prompting/` — Claude Code
- `~/.agents/skills/ai-prompting/` — Codex CLI / IDE, Gemini CLI, Grok Build (one shared copy)
- `~/.vibe/skills/ai-prompting/` — Mistral Vibe
- `~/.qwen/skills/ai-prompting/` — Qwen Code
- `~/.cursor/commands/ai-prompting.md` — Cursor, a one-line command that points at the shared copy

Pass `--list` to see the targets, `--host <id>` to pick one, `--dry-run` to preview, `--force` to
overwrite. For a single project, copy the directory into the repo's own skills folder instead
(`.claude/skills/ai-prompting/` or `.agents/skills/ai-prompting/`).

**Upgrading from 0.3.x:** the separate `/ai-prompting:improve` command is gone — it was a second
entry for the same Skill. The installer removes `~/.claude/commands/ai-prompting:improve.md` when it
installs the Claude Code skill.

## Usage

The host triggers the Skill from its description when you ask to improve a prompt, or you invoke
it directly — `/ai-prompting` in Claude Code, `$ai-prompting` in Codex:

<CodeBlock code={`/ai-prompting <your prompt here>`} />

You can pass the same flags as the CLI, plus `--target` for a model or vendor:

<CodeBlock code={`/ai-prompting write a launch email --mode diagnostic --audience "B2B founders" --target gpt-6`} />

Natural-language fallbacks work too:

<CodeBlock code={`/ai-prompting scrivimi un'email di lancio in italiano, non chiedere`} />

"Native" hosts load `SKILL.md` from their skills directory. "Adapter" hosts reach it another way —
ChatGPT through plugins (`agents/openai.yaml` supplies the UI metadata), Cursor through a one-line
command that points at the installed Skill. The list contains only hosts whose skills location we
have checked against their documentation; any other host on the Agent Skills standard should work
by copying the directory into its skills folder.

## How the Skill works under the hood

1. The host loads `SKILL.md`. The frontmatter tells it when to trigger; the body explains the
   9-step decision flow.
2. When the user invokes `/ai-prompting` with flags, the Skill maps them onto its own Options
   table — there is no separate command file to drift. It classifies the input and, if needed,
   loads `references/*.md` for deeper rules; when you name a target model, it looks up that
   model's row in the capability matrix (reasoning control, sampling, structured output, tools).
3. The agent does the semantic rewrite using its own LLM. Padding is stripped, the canonical XML
   scaffold is filled in, assumptions are made explicit, and a 0–100 score is estimated.
4. The output is rendered in the format defined by `--mode`.

The Skill is pure markdown. No code is downloaded and no network calls happen at install time.

## Troubleshooting

If the Skill doesn't show up, check the target paths and run the doctor:

<CodeBlock code={`node node_modules/ai-prompting/scripts/install-skill.js --list
ai-prompting doctor`} />

The doctor checks the `SKILL.md` frontmatter, that its references ship with the package, and that the CLI
runs.
